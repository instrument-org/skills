Incident review · Tuesday, Oct 20, 14:02 to 14:43

Our own retries took checkout down for 41 minutes

A short rate limit from the payment provider became an outage because every request retried five times.

41 mincheckout failing

5×calls per payment while limited

  1. Pay buttoncustomer taps Pay
  2. checkout.tsbuilds the order
  3. retryPayment5 tries, no wait
  4. provider APIanswers 429
  5. error screenasks to try again

What happened, minute by minute

TimeWhat we saw
14:02Provider returns 429 for 3% of calls, a normal burst limit.
14:03Each failed call retries five times at once; traffic to the provider triples.
14:09Provider limits our whole account. Every checkout fails.
14:31Retries switched off by flag. Errors start falling.
14:43Limit lifts. Checkout succeeds again.

The fix is one retry that waits

A 429 tells us when to try again. We now wait that long, once, instead of hammering the provider.

- const RETRIES = 5;
- const WAIT_MS = 0;
+ const RETRIES = 1;
+ const waitFor = (res: Response) => Number(res.headers.get("retry-after") ?? 1) * 1000;
